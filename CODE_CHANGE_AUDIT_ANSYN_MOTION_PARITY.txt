PURPOSE

This document defines the code changes required to transform the current Figma Make output from a mostly static editorial portfolio into a high-fidelity, motion-led experience with the same level of interaction depth, pacing, and technical finish as the Ansyn reference. It does not authorize copying Ansyn's source code, assets, branding, text, or exact compositions. Recreate the interaction mechanisms with Toni's original content and visual identity.

EXECUTIVE VERDICT

The current build is visually competent but motion-architecturally incomplete. It resembles a dark portfolio template with a few animated decorations. Ansyn behaves like a continuous audiovisual system in which navigation, typography, scrolling, canvas rendering, pointer input, section transitions, and route transitions all share one motion language.

The current implementation includes only:

1. A five-line clip-path entrance in the hero.
2. A low-opacity drifting text canvas.
3. A small hero heading fade.
4. Clip-path image reveals in Featured Work.
5. Height animation for Project Index quick views.
6. A conventional sliding mobile drawer.
7. Basic hover translations and color changes.

It does not include the mechanisms that create Ansyn's identity:

1. A long pinned hero journey with scroll-scrubbed typography.
2. Continuous interpolation between large typographic states.
3. A visual scene that evolves from abstract text into a meaningful interactive object.
4. Scroll-responsive navigation that changes form.
5. Inertial dragging and momentum.
6. Pointer-reactive typography, magnetic controls, or proximity effects.
7. Full-screen route curtains and transition choreography.
8. FLIP-style project-row expansion.
9. Text scramble or decode behaviors.
10. A coherent continuation of motion through the middle and final sections.

The result is therefore not a weaker version of Ansyn. It is a different interaction model.

IMPORTANT SPECIFICATION CONFLICT

The imported portfolio specification explicitly instructed the generator to use quieter motion and not reproduce Ansyn's exact composition. The output followed the conservative interpretation of that instruction. If the goal has changed to motion parity, the implementation brief must now explicitly prioritize interaction fidelity, scroll choreography, and scene continuity while still preserving original content and assets.

1. src/portfolio/PortfolioHero.tsx is a normal 100svh hero. It is not a multi-viewport journey and has no sticky stage.
2. Its CanvasField only moves small vocabulary tokens at constant random velocities. It does not react to scroll progress or pointer distance.
3. src/portfolio/FeaturedWork.tsx uses only one-time clip-path reveals and image hover scaling.
4. src/portfolio/ProjectIndex.tsx updates React state on every mousemove for its spotlight and preview. It has no spring interpolation, momentum, tilt, clipping choreography, or FLIP measurement.
5. src/portfolio/PortfolioNav.tsx remains a fixed conventional bar. It does not collapse into a circular trigger after leaving the hero.
6. src/routes.tsx provides route splitting but no transition boundary or full-screen route curtain.
7. package.json does not include Lenis or an equivalent inertial scroll controller.
8. The active portfolio route contains no sticky section at desktop width. At 1280 by 720, the page measured 8,958 pixels tall, but none of its portfolio sections used position: sticky.
9. The production build passes, but the main JavaScript bundle is approximately 485 KB raw and 151 KB gzip before adding the missing interaction system.
10. Several project images were still unloaded during the visual review because all covers depend on remote Unsplash URLs. This creates empty dark frames and makes the portfolio presentation network-dependent.
11. .figma/make/site.json still describes a generic document-management application and disables indexing.
12. There are two competing portfolio implementations: active files directly under src/portfolio and an apparently unused duplicate tree under src/portfolio/components plus src/portfolio/content. This increases ambiguity for future agents.

REFERENCE MOTION SYSTEM TO RECREATE

Use the following professional terminology consistently in code comments and implementation notes:

1. Pinned scrollytelling: a multi-viewport section with a sticky 100svh stage.
2. Scroll scrubbing: animation values are derived continuously from normalized scroll progress, not triggered once.
3. Kinetic typography: oversized words move, fade, scale, and exchange hierarchy as the user scrolls.
4. Procedural canvas typography: a seeded Canvas 2D field generates evolving text textures behind the main type.
5. Typographic overprint: ghost copies, offset echoes, and clipped duplicates create depth without images.
6. Clip-path strip reveal: horizontal masks reveal words in staggered strips.
7. Scanline sweep: a subtle, slow horizontal or vertical light line passes through the scene.
8. Inertial drag: pointer velocity continues after release and decays with friction.
9. Scroll-responsive navigation: the full navigation changes into a compact circular trigger after a threshold.
10. Curved off-canvas reveal: a navigation panel enters with a curved masking edge rather than a rectangular slide.
11. Magnetic interaction: controls shift toward the pointer within a limited radius and spring back.
12. Character-level proximity animation: individual letters react to pointer distance.
13. Cursor-following preview: project imagery follows the pointer with spring lag, bounded positioning, rotation, and clipping.
14. FLIP transition: First, Last, Invert, Play measurement animates expanding rows without layout jumps.
15. Text scramble or decode: project labels transition through temporary glyphs before resolving.
16. Full-screen route curtain: a labeled wipe covers the viewport during route changes.
17. Section color inversion: background and text palettes transition at narrative boundaries.
18. Reduced-motion substitution: motion is replaced by immediate or opacity-only state changes while preserving all information.

TARGET EXPERIENCE

The portfolio should preserve Toni's evidence-led thesis but use motion as the organizing system. The opening sequence should communicate this progression:

QUESTION -> EVIDENCE -> DECISION -> SYSTEM -> OUTCOME

Those words must not simply appear as five stacked lines. They must exchange dominance during scrolling. Each word should become the active state, affect the procedural field, and resolve into evidence later in the page.

The second major scene should be an original Evidence Atlas, not a copy of Ansyn's globe. It can use a draggable spherical or orbital field with labeled project nodes: Tokenta Workflow OS, ALLWEB3 Escrow, Next Card, CyberOrigin Signals, AI Evaluation Harness, and Generative Type Field. This provides the same transition from abstraction to an interactive object while remaining semantically appropriate to the portfolio.

PHASE 1: BUILD A SHARED MOTION KERNEL

Create src/motion/MotionKernel.tsx.

Responsibilities:

1. Instantiate Lenis on desktop only when resolved motion mode is Full.
2. Use one requestAnimationFrame loop for Lenis, scroll progress, pointer smoothing, and canvas subscribers.
3. Expose normalized scrollY, velocity, direction, viewport size, pointer position, pointer velocity, and document visibility.
4. Pause all subscribers when document.hidden is true.
5. Use matchMedia to disable enhanced pointer effects below 768 pixels or when pointer: coarse.
6. Keep native scroll as the fallback.
7. Do not call React setState on every animation frame. Store hot values in MotionValues or refs and write transforms directly through Motion.

Update src/motion/MotionContext.tsx.

1. Keep Auto, Reduced, and Full.
2. Auto must follow prefers-reduced-motion.
3. Full must enable the complete experience unless the device is coarse-pointer mobile.
4. Add resolved capability flags: canSmoothScroll, canUsePointerFX, canUseCanvasMotion, and canPinScenes.
5. Apply a data-motion attribute to document.documentElement so CSS can branch cleanly.

Update package.json.

1. Add lenis as a runtime dependency.
2. Do not add a second large animation framework.
3. Keep motion/react as the primary animation library.

PHASE 2: REPLACE THE HERO WITH A PINNED JOURNEY

Replace src/portfolio/PortfolioHero.tsx with a component composition:

1. PortfolioHeroJourney.tsx
2. ProceduralTypeField.tsx
3. HeroWord.tsx
4. HeroScanline.tsx

Required layout:

1. Outer section height: 260svh to 300svh on desktop.
2. Inner stage: position sticky; top: 0; height: 100svh; overflow: clip.
3. Keep the real H1 and supporting thesis in semantic HTML.
4. Place the procedural field behind the words.
5. Keep the nav readable above the scene.

Required scroll choreography:

1. Progress 0.00 to 0.12: QUESTION enters through staggered horizontal strips.
2. Progress 0.12 to 0.30: EVIDENCE becomes dominant; QUESTION moves toward the upper-left and loses opacity.
3. Progress 0.30 to 0.48: DECISION crosses the center on a different axis; the field density increases.
4. Progress 0.48 to 0.68: SYSTEM scales from the lower field and becomes the structural anchor.
5. Progress 0.68 to 0.84: OUTCOME enters in cobalt and becomes the only fully saturated word.
6. Progress 0.84 to 1.00: typography separates to reveal the Evidence Atlas below.

Do not use five simple React entrance animations. Derive x, y, scale, opacity, blur, letter spacing, and color from continuous scroll progress using useTransform or equivalent interpolation.

Procedural field requirements:

1. Seed token positions so the first frame is deterministic.
2. Use Toni's vocabulary: question, evidence, constraint, state, decision, system, outcome, audit, prototype, release, validation, recovery, interface, model.
3. React to scroll velocity by stretching or offsetting tokens slightly.
4. React to pointer position with a bounded repulsion or clarity radius.
5. Include an overprint layer with clipped text echoes.
6. Cap device pixel ratio at 1.5 desktop and 1.0 mobile.
7. Render a static first frame before the animation loop starts.
8. Stop rendering when the hero is offscreen.
9. Reduced mode must display one stable composition without scanline, blur, or movement.

PHASE 6: MAKE THE PROJECT INDEX FEEL ALIVE

Rewrite src/portfolio/ProjectIndex.tsx.

Problems in the current code:

1. onMouseMove calls setState continuously and rerenders the row.
2. The preview uses a fixed top offset and only animates the left property.
3. Quick-view expansion animates height but does not measure and invert surrounding rows.
4. Labels do not decode or respond at the character level.

Required implementation:

1. Store pointer coordinates in MotionValues.
2. Use useSpring for preview x, y, rotation, and scale.
3. Clamp the preview inside the viewport and keep it away from the active row label.
4. Reveal the image with clip-path and a slight rotational settle.
5. Add text scramble on hover or focus, with the original accessible label remaining intact.
6. Implement FLIP expansion: measure row positions before and after open-state changes, invert transforms, and animate to zero.
7. Animate content opacity and y separately from row height.
8. Preserve keyboard operation and touch-friendly inline thumbnails.
9. Disable follower previews, scramble, and FLIP displacement in Reduced mode.

PHASE 10: PERFORMANCE, ACCESSIBILITY, AND RESPONSIVE RULES

Performance requirements:

1. Maintain one animation-frame scheduler.
2. Avoid React state updates during pointermove, scroll, and every animation frame.
3. Animate transform, opacity, filter, and clip-path only where possible.
4. Use ResizeObserver instead of repeatedly measuring layout during scroll.
5. Keep Canvas 2D DPR capped.
6. Pause canvas and pointer loops when offscreen or hidden.
7. Lazy-load case-study routes and noncritical scenes.
8. Target a main-route JavaScript budget below 190 KB gzip after adding the motion kernel.
9. Replace remote image dependencies with optimized local AVIF or WebP assets and responsive srcset.
10. Avoid permanent backdrop-filter on large layers if it causes frame drops.

Accessibility requirements:

1. All content must remain present in source order.
2. Canvas is aria-hidden unless it communicates a meaningful state; meaningful data must have an HTML equivalent.
3. All pointer interactions require keyboard equivalents.
4. Focus indicators must remain visible above animated layers.
5. The menu must retain its focus trap and Escape behavior.
6. The Motion setting must be keyboard accessible and persistent.
7. Reduced mode must remove smooth scrolling, scrubbing, inertia, scale, blur, scanlines, scramble, magnetic movement, route curtains, and cursor-following previews.
8. Do not rely on motion or color alone to express project status.

Responsive requirements:

1. Desktop 1440 and above: full hero journey, canvas field, Evidence Atlas, pointer effects, full navigation transformation.
2. Tablet 768 to 1439: shorten the hero journey to about 210svh, reduce field density, keep the atlas drag interaction, simplify word paths.
3. Mobile below 768: normal document flow, no pinned hero, no cursor follower, no smooth scroll, no magnetic displacement, static atlas with tap targets, and no horizontal evidence rail.
4. Test at 390 by 844, 768 by 1024, 1280 by 720, and 1440 by 900.
